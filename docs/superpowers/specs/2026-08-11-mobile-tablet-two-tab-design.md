# สเป็กปรับหน้า iPad/มือถือเป็น 2 แท็บและใช้ข้อมูลล่าสุดจาก Google Sheet

วันที่: 11 สิงหาคม 2026

## เป้าหมาย

ปรับ Printer Management Pro สำหรับ viewport ไม่เกิน 1024px ให้ใช้พื้นที่เต็มหน้าจออย่างมีประสิทธิภาพ โดยไม่มี page scroll แนวตั้งหรือแนวนอน ลดเมนูหลักเหลือ 2 แท็บ และให้ Google Sheet เป็นแหล่งข้อมูลล่าสุดเมื่อเปิดหน้าหรือกลับเข้ามาที่แท็บแอป

Desktop ตั้งแต่ 1025px ขึ้นไปยังใช้โครงสร้างเดิม ยกเว้นการนำ MAC Address ออกจากทั้งระบบ

## ข้อกำหนดที่ยืนยันแล้ว

- เมนู iPad/มือถือเหลือ 2 แท็บ:
  - `จัดการ` รวมฟอร์มเพิ่ม/แก้ไข เครื่องมือฐานข้อมูล เครื่องมือ TCP Scan และภาพรวม
  - `รายการ` แสดงเฉพาะตัวกรอง รายการเครื่องพิมพ์ และ pagination เต็มพื้นที่ ไม่มีการ์ดอื่นมาเบียด
- ปัดซ้าย–ขวาบนพื้นที่เนื้อหาเพื่อสลับ `จัดการ ↔ รายการ`
- ตัด MAC Address ออกจากฟอร์ม ตาราง ค้นหา CSV ข้อมูลฝั่ง client และ schema ฝั่ง Apps Script
- ฟอร์ม iPad/มือถือใช้ 2 คอลัมน์:
  - ชื่อเครื่องพิมพ์เต็มแถว
  - IP Address + สถานที่
  - รุ่น/ประเภท + หมายเหตุ
  - ปุ่มบันทึกเต็มแถว
- แท็บรายการใช้แนวทาง A: คำนวณจำนวนแถวต่อหน้าให้พอดีกับความสูงที่เหลือโดยอัตโนมัติ
- โหลดข้อมูลล่าสุดจากชีตเมื่อเปิดหน้า และทุกครั้งที่กลับเข้ามาที่แท็บแอป

## การออกแบบ UI

### Compact app shell

- ใช้ความสูง `100dvh` และ safe-area inset
- `body` และ container หลักไม่เกิด page overflow
- ส่วนหัวอยู่ด้านบน เนื้อหาแท็บกินพื้นที่ที่เหลือ และ navigation 2 แท็บอยู่ด้านล่าง
- navigation ใช้ 2 คอลัมน์เท่ากัน touch target อย่างน้อย 44px
- เมื่อความสูงจอสั้นหรืออยู่แนวนอน ให้สลับแท็บจัดการเป็นโครงสร้างซ้าย/ขวาเพื่อลดความสูง

### แท็บจัดการ

- iPad แนวตั้ง: ฟอร์มอยู่คอลัมน์ซ้าย เครื่องมือและภาพรวมซ้อนกันในคอลัมน์ขวา
- มือถือแนวตั้ง: ฟอร์มอยู่ด้านบน ตามด้วยเครื่องมือแบบ 3 คอลัมน์ 2 แถว และภาพรวม 2 ช่อง
- มือถือ/iPad แนวนอนหรือความสูงน้อย: ใช้ฟอร์มซ้ายและเครื่องมือ/ภาพรวมขวา
- ลด padding และ gap เฉพาะ compact layout โดยไม่ลดข้อความสำคัญต่ำกว่าเกณฑ์อ่านได้
- ปุ่มทุกปุ่มใน compact layout สูงอย่างน้อย 44px และมี focus/pressed state เดิม

### แท็บรายการเต็มหน้าจอ

- แสดงเฉพาะ filter bar, ตาราง/รายการ, page info และปุ่มก่อนหน้า/ถัดไป
- ไม่มีฟอร์ม เครื่องมือ หรือภาพรวมอยู่ใน DOM flow ของแท็บนี้
- compact row ใช้ความสูงคงที่และจำกัดข้อความยาวด้วย line clamp เพื่อให้คำนวณจำนวนแถวได้แน่นอน
- แสดงข้อมูลหลัก: ชื่อ, IP, สถานที่/ประเภท, สถานะ และปุ่มจัดการ โดยไม่มี MAC
- คำนวณจำนวนแถวจากความสูงของพื้นที่รายการหลังหักส่วนหัว ตัวกรอง pagination และ navigation
- คำนวณใหม่เมื่อ resize, orientation change หรือ `visualViewport` เปลี่ยน
- Desktop ยังคงตัวเลือกจำนวนแถวปัจจุบัน ส่วน compact ใช้ค่าอัตโนมัติและไม่แสดงตัวเลือก 15/50/100/all

## พฤติกรรม swipe

- รายการ view มีเพียง `manage` และ `list`
- ปัดซ้ายจาก `จัดการ` ไป `รายการ` และปัดขวากลับ
- ต้องเคลื่อนที่แนวนอนเกิน threshold และมากกว่าแนวตั้งอย่างชัดเจน
- ไม่เริ่ม swipe จาก input, select, textarea, button หรือลิงก์ เพื่อไม่แย่ง gesture ของ control
- navigation ที่มองเห็นได้ยังเป็นทางเลือกหลักสำหรับผู้ใช้ที่ไม่ใช้ gesture
- hash เดิม `#mobile-form`, `#mobile-tools`, `#mobile-overview` จะถูกแปลงเป็น `#mobile-manage`; `#mobile-list` ยังใช้ได้

## การนำ MAC Address ออกจากระบบ

### Client

- ลบ input และ validation ของ MAC
- ลบ `mac` จาก model, sample data normalization, การเพิ่ม/แก้ไข และ localStorage รุ่นใหม่
- migration localStorage จะอ่านข้อมูลเดิมแล้วทิ้ง property `mac`
- ลบ MAC จาก table cell, mobile inline detail, search และ CSV export
- เปลี่ยนหัวตารางจาก `IP & MAC Address` เป็น `IP Address`

### Apps Script และ Google Sheet

HEADERS ใหม่มี 9 คอลัมน์:

1. ID
2. Printer Name
3. IP Address
4. Location
5. Type
6. Status
7. Last Updated
8. Note
9. Synced At

ก่อนลบคอลัมน์ `MAC Address` จากชีต `Printers` ระบบจะสร้างชีตสำรองแบบซ่อนชื่อ `Printers_MAC_Backup_<timestamp>` หนึ่งครั้ง แล้วจึงลบคอลัมน์จริงและจัด header ใหม่ ชีตสำรองไม่ถูกอ่าน แสดง หรือ export โดยแอป และเก็บไว้เพื่อ rollback เท่านั้น การลบชีตสำรองในภายหลังเป็นงานแยกที่ต้องขออนุมัติอีกครั้ง

การ migration นี้เป็นการเปลี่ยน schema ของ Google Sheet และจะทำเฉพาะหลังผู้ใช้อนุมัติสเป็กนี้

## การดึงข้อมูลล่าสุดจากชีต

### Backend

- เพิ่ม public function `getPrintersFromSheet()`
- อ่านข้อมูลตามชื่อ header ไม่ผูกกับเลขคอลัมน์ เพื่อรองรับชีตเดิมที่ยังมี MAC ระหว่าง rollout
- คืน `{ ok, printers, syncedAt, schemaVersion }`
- normalize และจำกัดขนาดข้อความด้วยกฎเดียวกับการบันทึก
- ใช้ Script Lock ระหว่าง migration/write เพื่อป้องกันการอ่าน schema ครึ่งทาง

### Client

1. เปิดหน้าจอด้วย localStorage ก่อนเพื่อให้ UI แสดงทันที
2. เรียก `getPrintersFromSheet()` ผ่าน `google.script.run`
3. เมื่อสำเร็จ ให้ข้อมูลจากชีตเป็น source of truth แทนข้อมูล local ทั้งชุด จากนั้นอัปเดต localStorage, filter, dashboard และรายการ
4. เมื่อ `visibilitychange` กลับเป็น visible หรือ `pageshow` ให้โหลดจากชีตอีกครั้ง
5. ป้องกัน request ซ้อนด้วย shared in-flight promise
6. ถ้ามี write ที่กำลังรอ ให้รอ write จบก่อน refresh
7. ถ้าฟอร์มกำลังแก้ไขหรือมีค่าที่ยังไม่บันทึก ให้เลื่อน refresh จนกว่าจะบันทึกหรือยกเลิก เพื่อไม่ให้ state ที่กำลังแก้ไขหาย

ห้ามเขียนข้อมูล local/bundled ทับชีตอัตโนมัติระหว่างเปิดหน้า การเขียนชีตเกิดจาก save/delete/status update/restore หรือปุ่มบันทึกลงชีตเท่านั้น

### Fallback และสถานะผิดพลาด

- ถ้าอ่านชีตไม่สำเร็จ ให้คงข้อมูล local ที่แสดงอยู่และตั้งสถานะ `data-sheet-sync="error"`
- แสดงข้อความแจ้งแบบไม่บล็อกว่ากำลังใช้ข้อมูลในเครื่อง
- ถ้าชีตยังไม่มี schema ให้ backend สร้าง header ใหม่และคืนรายการว่าง โดยไม่ส่ง bundled data ไปเขียนทับอัตโนมัติ
- เมื่อ refresh สำเร็จ ให้ตั้ง `data-sheet-sync="synced"` และบันทึกเวลาที่โหลดล่าสุด

## ขอบเขตการทดสอบที่ตกลงใช้

### Browser/DOM seam

- 320x720, 440x956, 812x375, 820x1180, 1024x768 และ 1025x768
- 1024px ลงมาเห็นเพียง 2 แท็บ; 1025px เป็น Desktop
- ไม่มี MAC ในฟอร์ม ตาราง ค้นหา หรือ CSV
- ฟอร์ม compact เป็น 2 คอลัมน์ตามสเป็ก
- แท็บจัดการและรายการไม่มี page overflow แนวตั้ง/แนวนอน
- จำนวนแถวปรับตามพื้นที่และ pagination ทำงานถูกต้อง
- swipe สลับแท็บ แต่ไม่ทำงานเมื่อเริ่มจาก control
- touch target อย่างน้อย 44px และรองรับ reduced motion

### Apps Script seam

- อ่านชีตใหม่ 9 คอลัมน์ได้ถูกต้อง
- อ่าน legacy sheet 10 คอลัมน์แล้วตัด MAC ออกจากผลลัพธ์
- migration สำรองชีตก่อนลบคอลัมน์ MAC และไม่ทำซ้ำ
- save เขียน 9 คอลัมน์ตาม schema ใหม่
- เปิดหน้า/กลับเข้าแท็บแล้วข้อมูลจากชีตแทน local cache
- เมื่ออ่านชีตล้มเหลว local fallback ยังใช้งานได้และไม่เขียนทับชีต

## สิ่งที่ไม่ทำในงานนี้

- ไม่เปลี่ยน breakpoint Desktop 1025px
- ไม่เปลี่ยนรูปแบบสีหรือ visual identity หลัก
- ไม่เผยแพร่ deployment ใหม่จนกว่าจะผ่านการทดสอบและได้รับอนุมัติแยก
- ไม่ลบชีตสำรอง MAC โดยอัตโนมัติ

## เกณฑ์เสร็จสมบูรณ์

- test ใหม่ต้องแดงกับโค้ดเดิมและเขียวหลังแก้
- regression test เดิมยังผ่าน
- browser verification ผ่านทุก viewport ที่กำหนด
- ตรวจหน้า Apps Script จริงว่าสามารถอ่านข้อมูลล่าสุดจากชีตเมื่อเปิดและกลับเข้าแท็บ
- รายงานไฟล์ที่เปลี่ยน คำสั่งทดสอบ และข้อจำกัดที่ยังเหลือ
